# V2-B 실험 구현·검증·판정

2026-10-31. 모형: **known-surplus-v1 하나**. 브랜치 `codex/v2-b-known-surplus-20261031`. **판정: 수정 필요·채택 보류. 실험 코드는 보존하고 기본 실행은 legacy로 유지한다.** V2-C 최적화·결과에 맞춘 보정·추가 선택 모형은 구현하지 않았다.

## 1. 판정 근거

필수 불변조건·재현성·legacy 동등성은 통과했다. 그러나 참여·판매가 줄고, 외부 재입찰 참고와 가격 분산 대리값의 차이는 다수 조건에서 커졌다. B-04의 낮은 입찰자 수·판매율에 가까워지는 일부 변화가 있어도, 다른 상품 시장의 수치에 가까워졌다는 것만으로 새 모델이 실제 LAYER7 행동을 더 잘 설명한다고 판단할 수 없다.

엄밀한 기간 일치 J&S 검증은 합성 표본이 부족했다. A-01 이동률·가격 수준은 직접 정답으로 만들 수 없다. 따라서 **기술적으로 유효한 실험이지만, 추가 가정을 정당화하는 일관된 실측 우위는 확인하지 못했다.** 테스트 통과를 모델 채택으로 바꾸지 않았다.

## 2. 실제 구현한 선택식

실제 조회에서 저장한 `(마지막 필요 입찰가 q, 보인 종료 e, 조회 시각 t_seen, 고정 개인 WTP v)`만 사용한다. 자기 입찰 응답에서는 자기 경매의 공개 응답 가격·종료만 갱신한다. 타인의 최신 가격·연장·낙찰 결과는 무료로 조회하지 않는다.

```text
free_budget = budget − spent − committed
current_surplus = v_i − q_i
alternative_score_j = similarity(i,j) × (v_j − q_j)
```

대안 j는 실제 발견했고, 알고 있는 마감이 남고, 예산으로 진입 가능하고, 아직 낙찰받지도 선두이지도 않은 경매다. 정보 유효기간 τ를 지정한 경우 그 기간 안의 조회만 사용한다. 현재 이익이 양수이고 더 좋은 대안 점수가 없으면 기존 입찰 스타일로 진행한다. 동점은 알고 있는 종료·경매 ID 순으로 정한다.

이는 **현재/과거 표시가 기반의 근시안적 비교 휴리스틱**이지 기대 낙찰 효용의 추정식이 아니다. 선두 약정·낙찰 지출은 기존 예산에만 반영하고 한계 WTP를 추가 차감하지 않는다. 구매 수량1 제한이 없으며 통제 테스트에서2개 구매도 확인했다. 더 나은 대안을 발견해도 자동 이동·새 방문·새 가격 갱신을 만들지 않고 현재 입찰만 보류한다.

개인 WTP의 식·값·분포는 그대로다. 실험은 실제 발견 시 개인 가치를 평가하므로 cache의 평가 시점·행 수와 난수 호출 수는 legacy와 달라질 수 있다. key 기반 고정 가치이며 새 WTP 상승이나 별도 경쟁 차감은 없다. 원 `max(similarity)` 포기와 새 비교식을 동시에 적용하지 않는다.

### 추가 가정과 파라미터

현재가를 미래 지불가의 대리로 쓰는 근시안성, s를 대안 관련성 배수로 쓰는 해석, 발견 시 개인 가치를 앎, 자기 응답·약정·정산 정보를 앎, 보유 상품을 새 대안에서 제외하고 예산으로만 처리하는 것, 동점 해소, 보류 후 기존 방문 흐름에 의존하는 것은 모두 **ASSUMED**다. 새 식 자체의 계수는 실측 추정하지 않았다.

유일한 추가 수치 설정은 **정보 유효기간 τ**다. 사전 고정한 주 실험은 마감까지 무제한, 민감도는60분·360분이다. 기존 유사도 숫자는 그대로지만 ‘포기 확률’에서 ‘관련성 배수’로 의미가 바뀌는 것은 새로운 가정이다. 결과가 좋은 τ를 골라 기본값으로 올리지 않았다.

사전 명세: [PREIMPLEMENTATION.md](/experiments/auction-simulator/validation/v2_choice/PREIMPLEMENTATION.md).

## 3. 재사용과 변경 범위

[simulator.py](/experiments/auction-simulator/src/v2_choice/simulator.py)는 AuditMarket를 상속하고 발견·자기 응답 기록과 선택 gate만 추가한다. [policy.py](/experiments/auction-simulator/src/v2_choice/policy.py)의 비교 함수는 Market 객체를 받지 않고 관측된 정보·자기 상태·유사도만 받는다. 대안 경매의 live price/close를 읽을 통로가 없다.

[consider.py](/experiments/auction-simulator/src/v2_choice/consider.py)는 원 함수에서 기존 포기 블록만 새 gate로 바꾼 고정 사본이다. 원 함수가 선택·스타일 실행을 분리하지 않아 이 부분 사본이 필요했고, AST 검사로 그 이전·이후 본문이 정확히 같은지 확인했다. 방문·이벤트 큐·호가·WTP·예산·outbid·watch·재방문·스나이프·정산은 그대로 상속한다.

`model='legacy'`는 원 AuditMarket 자체를 반환한다. V2-A 코드와 큰 관찰 trace는 실험 경로에 붙이지 않았다. 실제 선택에 필요한 마지막 정보와 작은 카운터만 저장하며 기본 상세 trace는0행이다.

신규 파일은 src/v2_choice, validation/v2_choice, data/experiments/v2b-20261031 아래뿐이다. 원 baseline·audit·V2-A·보정·자료를 수정하지 않았다.

## 6. 실측 비교와 비교할 수 없는 항목

### 기간을 엄밀히 맞춘 J&S는 표본 불충분

J&S3일 경매의 기존30% holdout은35경매·234 bidder-auction쌍이다. 참조값은 입찰자6.686, 쌍당 입찰1.996, 재입찰44.87%였다. 그러나 합성 자료에서 **실제 정확72h인 입찰 경매는 A–E7,500개 중3개뿐**, F에는 없었다. 각 C/D/E seed1에1개이며 seed2·3에는 없다.

원 World는 명목 기간을 고른 뒤 선호 시각으로 마감을 정하므로 실제 기간이 정확72h인 경우가 드물다. 종료 정책이나 World를 정답에 맞게 바꾸지 않았다. 3개만 남긴 평균을 전체 검증처럼 쓰지 않고 **이 지표의 오차·유의성·채택 점수는 공란**으로 뒀다. 원수치·지원량만 case_metrics.csv에 보존했다. 집계표에서도 해당 평균은 제거했다. [ANALYSIS_LIMITS.md](/experiments/auction-simulator/validation/v2_choice/ANALYSIS_LIMITS.md)에 이유를 기록했다.

### A-01 이동 패턴

A-01의804명 문자열 중177명(22.01%)이 여러 경매에 참여했고, 연속 전환395/1544=25.58%, 그중 이전 경매가 열린 전환246/395=62.28%였다. 이번 합성은 서로 다른 상품·관측 기간·경매 수를 가진 전체 시장이고 같은 시각 입찰의 정렬도 영향을 준다. **22% 등에 맞춘 오차 점수는 만들지 않았다.** 모델 간 이동 지표 변화와 위 관측 사실만 나란히 제시했다. B-04의 마스킹 입찰자 ID로 추가 독립 이동 검증을 만들지 않았다.

주 실험의 유효 대안 비교에 사용된 정보 나이는 전체18개 카운터 기준 평균 **570.4분(9.51시간)**, 최대 **70.29시간**이었다. 실제 현재 가격과의 오차를 알고 있다는 뜻은 아니다. 오래된 저가 대안을 더 좋은 기회로 판단해 현재 입찰을 포기할 수 있고, 보류 후 그 대안을 실제로 재조회·구매할 보장도 없다. 이 경로가 적합도 변화를 일으켰다는 인과적 분해까지 검증한 것은 아니다.

짧은 유효기간은 일부 결과를 legacy에 가깝게 돌리지만 그 시간이 실측된 것은 아니다. τ를60분으로 고정하면 성공이라고 처리하거나 새 보정값으로 채택하지 않았다.

## 9. 복잡도와 성능 비용

방문·스타일 계수는 그대로 두고 정보 book·순위 비교·새 수치 설정1개(τ)를 추가했다. 새 연속 WTP·경쟁 계수는 없지만 의미상 가정 수는 늘었다. 고정 consider 사본은 부모 업데이트 때 AST 검사가 필요한 유지보수 비용도 있다.

A seed1(1,500명·500경매·30일)을 같은 World로 각3회 측정한 초기화+run 중앙값이다. World 생성·CSV·검증 hashing은 제외했고 회귀 worker는 종료했다. 다른 시스템 부하는 통제하지 않았다.

| 모드 | 중앙값 |
|---|---:|
| legacy | 2.960초 |
| 주 실험 | 3.702초 |
|60분 | 3.659초 |
|360분 | 3.587초 |
| V2-A 전체 observer | 8.987초 |

주 실험은 legacy의 **1.25배**, V2-A 전체 observer 시간의 **41.2%**였다. 모델 간 입찰·재방문 수와 기록량도 달라 순수 비교 함수의 추가 비용이나 observer 최적화 효과만으로 해석하지 않는다. 200명·60경매 별도 tracemalloc peak는 legacy2.27MiB, 주 실험2.48MiB, V2-A17.71MiB다. 이는 생성된 World를 제외한 작은 사례의 Python 할당이며 전체500경매 RSS가 아니다. 상세 trace는 기본0행이고 작은 카운터만 추가 출력한다. 따라서 모든 과거 대안 비교를 저장 파일만으로 재구성할 수는 없고, 개별 판단을 더 조사하려면 동일 seed 재실행과 국소 trace가 필요하다.

## 10. 유지·수정·폐기 판정

**기술적 기각 사유는 발견되지 않았다. 그러나 채택은 보류하고 수정 대상으로 분류한다.**

- 유지할 것: 실제 발견 정보만 사용하는 분리 구조, 고정 WTP·자기 예산·보유 상태 구분, 원 엔진 전환 경로와 재현 검증. 실험 코드도 비교 기준으로 보존한다.
- 수정 전 필요한 근거: 실제 조회·재조회·가격 신선도·상회 알림에서 무엇을 알았는지, 보류 후 실제 대안으로 이동했는지, 복수 구매 의도·보유 상품의 한계 수요. 현재 book은 상회로 약정이 해제돼도 과거 가격을 자동 추론·갱신하지 않아 낙관적인 대안을 오래 남길 수 있다.
- 폐기/미채택할 주장: 이 수식이 실증적으로 우월하다, τ 특정값이 정답이다, 추천 성과가 좋으면 채택한다는 주장. 그것을 뒷받침할 자료가 없다.

이번에 정보 갱신·방문 전환의 추가 변형을 구현하거나 결과를 개선하려고 숫자를 바꾸지는 않았다. V2-C 종료 추천 정책을 만들거나 최적화하지도 않았다. 기본 모드가 legacy인 이유다.
