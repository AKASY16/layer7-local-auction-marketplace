# 프로젝트 기획

## 1. 현재 방향과 문제 정의

LAYER7은 전국 수집품 대상 경매 플랫폼으로 전환합니다. 2026-10-29·2026-11-01 결정은 [결정 로그](04-decisions.md)에 남기며, 이전 지역 중고거래 기획은 Git 이력으로 보존합니다.

관심 있는 구매자가 흩어져 있으면 경매에 참여할 기회를 놓치기 쉽습니다. 타임 경매는 상품과 일정을 미리 알리고 정해진 시각에 짧게 진행해 참여를 한 시간대로 모읍니다. 다만 사전 예고가 실제 참여를 늘리는지는 검증되지 않았으며, 이를 성과로 주장하지 않습니다.

## 2. 최종 시연 목표

최종 시연에서는 다음을 중심으로 보여줍니다.

1. 최소 경매 MVP: 상품 등록부터 낙찰 확정까지.
2. 타임 경매: 예고·관심상품·시작 알림·30분 실시간 입찰·마지막 1분 자동 연장.
3. 마감 직전 입찰과 연장·종료가 겹쳐도 결과가 하나로 정해진다는 동시성 테스트와 입찰 성능 측정.

수요 기반 매칭·마감 편성은 2026-11-01 뺐고, 이상입찰 탐지는 2026-10-31 보류했습니다([보류 계획](later/anomaly-bid-detection.md)). 관심 사용자 수는 예상 입찰자 수가 아닙니다.

## 3. 핵심 사용자와 최소 흐름

- 구매자: 예고된 타임 경매를 관심상품으로 등록하고, 시작 알림을 받아 입찰에 참여합니다.
- 판매자: 상품을 등록하고 일반 경매 또는 타임 경매를 만듭니다.

테스트 계정 → 이미지 업로드·상품 등록/이미지 표시 → 경매 생성/조회 → 수동입찰·이력 → 종료·낙찰 확정이 최소 경매 흐름입니다. 기존 입찰 엔진의 정합성을 유지합니다. 상세 범위는 [요구사항](02-requirements.md), 검증은 [P1 실험 계획](p1/experiments.md)을 따릅니다.

## 4. 범위와 미결정 사항

상품의 최초 이미지 업로드·등록·표시는 최소 MVP에 포함합니다. 등록 후 이미지 추가·삭제·재정렬과 정리 배치, HTTP 요청 멱등 기능, 자동입찰·Trade·신뢰점수 변경·배송·결제·채팅·푸시 알림은 후순위입니다. WebSocket 화면 갱신과 앱 내부 알림은 P1에 포함합니다. 전국 탐색 전환과 기존 지역 데이터 삭제는 별개이며 현재 지역 계약을 유지합니다.

정확한 발표일·세부 API/ERD는 미정입니다. 개인별 책임은 각 이슈의 Assignees와 [협업 규칙](00-team-and-collaboration.md)을 따릅니다.
