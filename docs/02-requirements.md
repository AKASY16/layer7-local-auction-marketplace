# 요구사항 및 기능 정의

## 현재 적용 범위 — 2026-10-29

전국 수집품 경매로 전환하며 아래 구분을 현재 개발 기준으로 사용합니다. 세부 작업은 [P1](p1/README.md), 변경 이유는 [결정 로그](04-decisions.md)를 참조합니다.

| 구분 | 범위 | 상태 |
|---|---|---|
| 기존 기반 | 가입·로그인·내 정보·지역·경매 목록·수동입찰 API, 홈·회원 화면, 동시성 테스트 | 구현됨 |
| 최소 경매 MVP | 최초 이미지 업로드·상품 등록·이미지 표시, 경매 생성/상세, 입찰 이력, 종료·낙찰 확정 | 추가 구현 필요 (#63~#65, #47) |
| P1-A | 논문 기반 이상입찰 특성·위험 점수·오탐 감소, 커밋 후 분석, 관리자 권한·화면 | 신규 개발 (#61, #66~#69) |
| P1-B | 구매 희망·가능 시간, 상품 동일성 매칭·수요 집계, 마감 추천·근거·화면 | 신규 개발 (#62, #70~#73) |
| 검증·시연 | 공개 데이터 비교, 합성 시나리오·독립 평가, 입찰 성능·분석 지연, 통합 시연 | 신규 작업 (#74~#76) |
| 후순위 | 자동입찰·Trade·신뢰점수 변경·이용 정지 고도화·범용 Push·배송·결제·채팅·Refresh·등록 후 이미지 편집/정리 배치·HTTP 요청 멱등 기능·재경매 | 이번 시연 필수 범위 밖 |
| 선택 | WebSocket 화면 갱신, 실시간 ML 추론, MRF/LOF·임베딩 확장 | 최소 목표 충족 후 검토 |

위 필수 범위가 동작하고 근거·한계를 설명할 수 있어야 완료입니다. 위험 점수로 자동 차단하지 않고 데이터 부족을 표시합니다. 유사 상품은 정확 일치 수요에 합산하지 않으며 개별 희망 가격 상한을 공개하지 않습니다.

상품 이미지는 최소 1장 이상 포함하고 기존 `imageKeys` 1~10장·JPEG/PNG/WebP·장당 10MB 이하 정책을 유지합니다. 업로드 URL 발급 → Object Storage에 PUT → 상품에 연결 → 조회 화면 표시가 최소 흐름입니다. 등록 후 추가·삭제·순서 변경과 만료 업로드 정리는 후순위입니다.

HTTP 요청 멱등성은 **테스트뿐 아니라 기능도 후순위**입니다. P1에서는 `Idempotency-Key`를 요구하지 않고 전달되어도 키 검증·요청 해시 저장·응답 재사용을 수행하지 않습니다. 분석 이벤트의 중복 처리 방지(#66)와 종료 Scheduler의 중복 실행 방지(#47)는 필수로 유지합니다.

아래는 **전환 전 상세 정책과 확장 설계**입니다. 가격·시간·수동입찰 규칙은 유지하되 자동입찰·거래 등은 위 구분에 따라 후순위로 읽습니다. 미구현 항목을 현재 동작하는 기능으로 간주하지 않습니다.

## 사용자

- 회원가입 / 로그인
- 닉네임 서비스 전체 UNIQUE
- 회원탈퇴 시 물리 삭제 대신 `WITHDRAWN`
- ACTIVE 상품, READY/OPEN 판매경매, OPEN 경매 현재 선두/ACTIVE AutoBid, 진행 중 Trade 의무가 있으면 탈퇴 불가
- 지역 설정: MVP에서는 시·군·구(자치구). 일반구가 있는 시는 시 하나로 묶음 (예: 수원시 장안구 → 수원시)
- 내 판매 / 입찰 / 낙찰 내역 확인
- 신뢰점수 표시

## 상품

- 전국 수집품 상품 등록. 상품군별 식별 속성은 #62에서 확정
- Category code: DIGITAL / HOME_APPLIANCE / FURNITURE / LIVING_KITCHEN / FASHION / BEAUTY / SPORTS_LEISURE / HOBBY_GAME / BOOK_MEDIA / ETC
- 이미지 업로드: MVP 1~10장, JPEG/PNG/WebP, 파일당 최대 10MB
- 이미지는 Presigned URL로 클라이언트가 Object Storage에 직접 업로드하고, 상품 등록 시 objectKey만 전달
- 상품 지역은 등록 당시 판매자의 현재 지역을 snapshot으로 저장하며, 이후 사용자가 지역을 변경해도 기존 상품 지역은 유지
- 지역별 조회 / 검색
- 상품 상태 등급
  - `UNOPENED`: 미개봉
  - `LIKE_NEW`: 거의 새것
  - `GOOD`: 양호
  - `FAIR`: 사용감 있음
  - `DAMAGED`: 하자 있음
  - `NEEDS_REPAIR`: 수리 필요
- `conditionDescription` 필수: 흠집, 파손, 기능 이상, 구성품 누락 등 상세 설명
- 경매 시작 전(경매 없음 또는 READY이고 startAt 전)이면서 과거 입찰이 없을 때만 상품 정보 수정 가능
- OPEN 경매는 입찰이 없어도 수정 불가, 경매 취소 후 수정
- 한 번이라도 입찰이 발생한 Product는 과거 경매 의미 보존을 위해 이후에도 기존 핵심정보와 상태정보 잠금
- 판매자는 READY/OPEN 경매에 1회 200자 이내의 `내용 추가`를 append 방식으로 등록 (입찰 여부 무관, 경매당 최대 10건)
- 경매 상세에는 같은 상품의 이전 경매에서 추가한 내용도 함께 표시

## 경매

- 시작 가격
- 예약 시작 시간
- 종료 시간
- 금액(시작가·입찰가·자동입찰 상한)은 10,000,000원 이하
- 경매 기간은 1시간 이상 7일 이하, 예약 시작은 7일 이내
- 상태: `READY / OPEN / ENDED / CANCELED`
- 수동 입찰
- 자동 입찰
- 자동입찰 설정: 최대 입찰 가격(maxAmount)
- 가격 상승폭은 사용자/판매자가 정하지 않고 서비스 공통 가격구간별 입찰단위표로 자동 계산
- 현재가 구간에 따라 수동입찰의 다음 최소 유효 금액과 자동입찰의 다음 금액을 동일 정책으로 계산
- 시작가, 수동입찰 금액, AutoBid maxAmount는 모두 해당 가격구간의 유효 단위에 맞아야 함
- 유효하지 않은 금액은 서버에서 거절
- 자동입찰 설정/변경 전 현재 가격구간의 단위, 다음 최소 입찰가, maxAmount를 안내하고 사용자 확인을 받음
- AutoBid는 경매가 열려 있는 동안 계속 실행되지 않고, 입찰/설정 변경 이벤트가 발생했을 때만 계산
- AutoBid 설정/변경은 즉시 경쟁에 참여하며, Bid 0건에서 첫 AutoBid가 설정되면 startPrice의 실제 AUTO Bid가 생성됨
- 현재 선두가 아닌 AutoBid가 자신의 maxAmount로 다음 유효 입찰가를 만들 수 없으면 EXHAUSTED
- 도전자의 입찰 금액 또는 maxAmount가 현재 선두의 상한과 같으면 현재 선두 우선
- 현재 선두는 수동입찰로 자기 가격을 올릴 수 없으며, 상한 조정은 AutoBid로 함
- AutoBid는 OPEN 경매에서만 설정 가능 (READY 중 사전 등록 미지원)
- 입찰 직전 금액과 철회 불가 안내
- 마감 직전 입찰에 따른 자동 연장 없음
- 입찰 가능 여부는 클라이언트 표시시간이 아닌 서버시간 기준
- `startAt <= now < endAt`에서만 입찰 가능
- Scheduler 상태 반영이 늦더라도 endAt 이후 입찰은 거절
- Scheduler 상태 반영이 늦더라도 startAt이 지났으면 입찰 가능
- 경매·거래 화면의 상태는 서버시간 기준 논리 상태로 표시하고, 종료 후 정산 완료 여부(finalized)를 함께 표시

## 낙찰 후 거래

- 낙찰자는 경매 `endAt` 기준 24시간 안에 거래 진행 또는 포기 선택
- 거래 진행 / 포기 / 미응답 / 취소 / 기한 만료 상태 관리
- 거래 기한은 `endAt` 기준 7일. 완료 요청과 취소는 이 안에서만 가능
- `IN_PROGRESS` 이후 판매자 또는 구매자 중 한 명이 거래 완료 요청
- 상대방이 확인해야 `COMPLETED`
- 상대방이 미완료로 판단하면 `IN_PROGRESS` 복귀
- 완료 요청을 받은 상대방은 거래 기한과 관계없이 요청 시점부터 최소 24시간의 응답 시간을 보장받음
- 응답 기한까지 확인/거절이 없으면 자동 완료, 완료 요청 없이 거래 기한이 지나면 `EXPIRED`
- 판매자·구매자 모두 일방 취소 가능, 취소한 쪽에 페널티
- 차순위 승계 없음
- 거래 실패 시 판매자 선택으로 새 Auction 생성

## 신뢰점수

- 초기값 0
- 정상 거래 완료: 판매자 +2 / 구매자 +2
- 낙찰 포기: 구매자 -5
- 24시간 미응답: 구매자 -10
- 거래 취소: 취소한 쪽 -5
- 거래 기한 만료(EXPIRED): 변동 없음
- MVP에서는 음수 허용, 별도 상·하한 없음
- 점수는 표시용이며 점수만으로 입찰을 막지 않음

## 이용 정지

- 본인 책임의 거래 실패(포기·미응답·본인 취소)가 3회 연속되면 7일간 입찰·경매 등록 정지
- 진행 중인 거래와 기존 의무 이행은 정지 중에도 가능
