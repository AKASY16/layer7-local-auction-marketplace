# 경매 정책 및 비즈니스 규칙

## 입찰

- 수동 입찰과 자동 입찰 모두 지원
- 성립한 Bid는 수정·삭제·철회하지 않음
- 입찰 전 최종 금액과 철회 불가 정책을 명확하게 표시
- 판매자는 본인 경매에 입찰할 수 없음
- 입찰 상승폭은 판매자나 입찰자가 직접 정하지 않고 **서비스 공통 가격구간별 입찰단위표**를 사용

## 가격구간별 입찰단위

MVP 기본 정책:

| 현재 가격 | 다음 최소 상승폭 |
|---|---:|
| 0 ~ 9,999원 | 100원 |
| 10,000 ~ 49,999원 | 500원 |
| 50,000 ~ 99,999원 | 1,000원 |
| 100,000 ~ 499,999원 | 5,000원 |
| 500,000 ~ 999,999원 | 10,000원 |
| 1,000,000원 이상 | 20,000원 |

- 서버의 `BidIncrementPolicy`가 현재 가격을 기준으로 다음 최소 입찰가를 계산
- 수동입찰도 이 최소 입찰가 이상이어야 함
- 자동입찰도 동일한 정책을 사용
- 정책은 서비스 공통 규칙이며 Auction별 설정값으로 저장하지 않음

예:
- 현재가 48,000원 → 최소 다음 입찰가 48,500원
- 현재가 80,000원 → 최소 다음 입찰가 81,000원
- 현재가 100,000원 → 최소 다음 입찰가 105,000원

## 자동입찰

사용자 설정값:
- `maxAmount`: 사용자가 지불할 의사가 있는 최대 입찰 가격

규칙:
- 사용자는 상승폭을 직접 설정하지 않음
- 다른 유효 입찰 또는 AutoBid 설정/변경 이벤트가 발생했을 때만 자동입찰 계산을 수행
- 경매가 OPEN인 동안 AutoBid가 지속적으로 CPU/Thread를 점유하지 않음
- 현재 가격에 대한 서비스 입찰단위표를 사용해 필요한 최소 금액만 자동입찰
- 최대금액을 초과하지 않음
- 같은 최대금액이면 `priorityAt`이 빠른 사용자가 우선
- 최초 등록 시 `priorityAt = now`
- `maxAmount` 변경 시 `priorityAt = now`로 갱신
- 최대금액 상향 가능
- 하향은 현재 성립 가격 미만으로 불가
- 자동입찰 중지 가능
- 이미 성립한 Bid는 설정 변경/중지 후에도 유지

### 최대금액 경계 처리

서비스 입찰단위 적용 결과가 `maxAmount`를 초과하더라도, `maxAmount`가 현재 최고 경쟁금액보다 높은 유효 금액이면 **maxAmount를 마지막 자동입찰 금액으로 사용할 수 있음**.

예:
- 경쟁자의 최대금액 99,500원
- 서비스 입찰단위상 다음 정상 가격은 100,500원
- 내 maxAmount가 100,000원
- 100,500원까지는 올릴 수 없지만 경쟁자보다 높은 100,000원까지는 입찰 가능 → 마지막 입찰 100,000원

반대로 현재 최고 경쟁금액 이상으로 유효하게 상회할 수 없다면 `EXHAUSTED` 처리.

### 설정 UX

자동입찰 설정/변경 전:
- 최대금액을 명확하게 표시
- 서비스가 가격구간별 입찰단위에 따라 자동으로 최소한만 올린다는 점 안내
- 최대금액 부근에서는 정규 입찰단위보다 작은 차이로 마지막 입찰이 형성될 수 있음을 안내
- 사용자가 확인한 뒤 AutoBid 활성화

## AutoBid 경쟁 처리

- DB에서 100원/500원/1,000원씩 반복 INSERT하며 핑퐁하지 않음
- 입찰 이벤트 발생 시 Auction row를 잠근 한 트랜잭션 안에서 경쟁 결과를 계산
- AutoBid가 여러 개면 최대금액과 동가 우선순위를 기준으로 최종 선두와 필요한 현재가를 결정
- 실제 가격 결정에 필요한 Bid만 저장하고 가상의 중간 상승단계는 모두 Bid 이력으로 만들지 않음
- 계산이 끝나고 Commit되면 WebSocket / Push를 전달

## 판매자 취소

- `READY`: 취소 가능
- `OPEN`: 입찰 0건이면 취소 가능
- 한 건이라도 입찰이 발생하면 임의 취소 불가

## 예약 및 종료

- 예약경매 지원
- `startAt` 전 `READY`
- `startAt` 도달 시 `OPEN`
- `endAt` 도달 시 `ENDED`
- 종료 직전 입찰에 따른 시간 연장 없음
- 경매 종료를 위해 Auction별 Thread/Timer를 점유하지 않음
- Scheduler가 `status + startAt/endAt` 인덱스를 기준으로 전이 대상 Auction을 조회
- 입찰과 종료 Scheduler는 동일 Auction에 대해 같은 쓰기 락 규칙을 사용

## 상품 내용

- 입찰 1건 이상이면 기존 핵심 상품정보 수정/삭제 불가
- 판매자는 기존 내용을 덮어쓰지 않고 `ProductAppend` 등록
- 1회 최대 200자

## 낙찰

- 차순위 승계 없음
- 입찰자가 없으면 유찰, Trade 생성 안 함
- 낙찰자가 있으면 Trade 생성
- 낙찰자 응답 기한 24시간

## 재경매

- 기존 Auction을 다시 OPEN으로 되돌리지 않음
- 판매자가 새 Auction 생성
- `relistedFromAuctionId`로 이전 경매 참조
- 기존 Bid / AutoBid / Trade 이력은 변경하지 않음
