# Frontend

주 담당: 박지우

## 기술
- React 19 + Vite
- JavaScript
- Styled Components
- React Router
- REST API
- WebSocket(STOMP)
- 반응형 웹

## 디자인 기준
- 목업은 색·모양·배치의 가이드로만 쓰고, 기능은 API 명세를 따른다 (목업과 디자인 값 표: #52)
- 색·글꼴·크기·간격·모서리는 `src/styles/theme.js`의 값만 쓰고, 화면 코드에 색 값을 직접 적지 않는다
- 버튼·입력칸·선택칸·오류 문구는 `src/components/common`의 공통 부품을 쓴다. 새 부품(칩, 배지, 경매 카드 등)은 처음 필요한 화면 작업에서 같은 디자인 값으로 만든다
- 흰 화면 기준이라 다크 모드는 지원하지 않는다. 휴대폰 폭이 기준이고 PC에서는 가운데 480px로 보인다
- 작은 글씨는 배경과 명암비 4.5:1 이상. 빨강(`danger`)은 남은 시간 전용이고 오류·경고 문구는 와인색(`primary`)으로 쓴다
- 금색(`gold`)·초록(`success`)은 흰 배경에서 명암비가 4.5:1에 못 미쳐 아이콘·장식에만 쓰고 작은 글씨에는 쓰지 않는다

## 주요 화면/기능
- 로그인 / 회원가입
- Access Token은 메모리에만 보관. 401을 받으면 `POST /auth/refresh`를 탭 간 한 번만 실행해 재발급받고, 실패하면 로그인 화면으로 이동
- Access Token을 갱신하면 WebSocket을 새 토큰으로 다시 연결
- 상품 목록 / 상세 / 등록
- 상품 상태 등급 / 상세설명
- 이미지 업로드 (업로드 URL 발급 → Object Storage에 직접 PUT → 상품 등록 시 objectKey 전달)
- 예약 경매 생성
- READY / OPEN / ENDED 상태 표시 (서버가 내려주는 논리 상태 기준, 입찰 버튼은 `status == OPEN`일 때만)
- `ENDED + finalized=false`는 "집계 중", `ENDED + finalized=true + winningBid=null`은 유찰로 표시
- 거래 상태도 논리 상태로 표시하고 finalized가 false면 반영 대기 중으로 표시
- 수동입찰 / 자동입찰 설정
- 자동입찰 설정/변경 확인 UI: maxAmount 표시
- 현재 가격구간의 유효 입찰단위와 다음 최소 입찰가 표시
- 시작가/수동입찰/maxAmount가 유효 단위에 맞는지 입력 즉시 검증 (`GET /bid-increment-policy`의 가격단위표 사용, 하드코딩 금지)
- 유효하지 않은 금액은 가까운 유효 금액 후보를 안내
- 자동입찰이 서비스 가격단위표에 따라 필요한 최소 유효 금액만 올린다는 안내
- 입찰 금액이나 자동입찰 상한이 현재 선두의 상한과 같으면 현재 선두가 우선한다는 안내
- 현재 선두에게는 수동입찰 대신 자동입찰 상한 조정 안내
- 입찰 최종 확인 UI
- 실시간 현재가 (경매별로 가장 큰 `version`을 기억하고 그보다 오래된 이벤트는 무시)
- 낙찰 후 거래 진행 / 포기
- 거래 완료 요청 / 상대방 확인
- 응답 기한·거래 기한·완료 응답 기한 표시
- 거래 취소 (취소한 쪽 페널티 안내)
- 거래 참여 정지 상태와 해제 시각 안내
- 재경매
- 신뢰점수
- 브라우저 Push 권한/구독
- 앱 내부 알림센터
