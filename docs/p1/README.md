# P1 — 최종 시연 범위

2026-10-29 방향 전환(#60), 2026-11-01 타임 경매 도입(#82). 현재 요구사항의 원본은 [02-requirements.md](../02-requirements.md)입니다. 이 문서는 목표와 작업 연결을 설명하며 구현 완료를 뜻하지 않습니다.

## 목표와 범위

전국 수집품 경매에 일반 경매와 **타임 경매**(예약형 30분 경매)를 두고, 마감 직전 입찰이 몰려도 결과가 하나로 정해진다는 것을 최종 시연에서 보여 줍니다. 타임 경매 규칙은 [경매 정책](../03-auction-policy.md#타임-경매)에 있습니다.

| 영역 | 필수 결과 | 작업 |
|---|---|---|
| 최소 경매 | 최초 이미지 업로드·상품 등록/표시·경매 생성/상세·수동입찰·이력·종료·낙찰 | #63~#65, #47. 기존 입찰 엔진 유지 |
| 기반 | WebSocket 화면 갱신, 관심상품, 앱 내부 알림, 상품·경매 화면 | #83~#90 |
| 타임 경매 | 유형·24~48시간 예고·30분 진행·마지막 1분 자동 연장·시작 알림·홈 "곧 시작" 목록 | 기반 작업 후 이슈 생성 |
| 검증 | 연장·종료 경합을 포함한 동시성 테스트, 입찰 성능 측정, 통합 시연 | #76 |

수요 기반 매칭·마감 편성은 2026-11-01 뺐습니다. 마감 시각 시뮬레이션 결과는 [실험 문서](experiments.md)에 남겨 두었습니다. 이상입찰 탐지는 2026-10-31 보류했고 계획은 [보류 계획](../later/anomaly-bid-detection.md)에 있습니다.

자동입찰·Trade·신뢰점수 변경·푸시 알림·배송·결제·채팅·Refresh·등록 후 이미지 편집/정리 배치·HTTP 요청 멱등 기능은 후순위입니다.

## 설계에서 지킬 경계

- 최초 상품 등록은 기존 1~10장 이미지 정책을 적용합니다. 업로드 URL → 파일 PUT → 상품에 연결 → 이미지 표시를 포함하고 이미지 없는 등록으로 대체하지 않습니다.
- HTTP 요청 멱등 기능과 C09 테스트는 함께 후순위입니다. P1에서 키는 필수가 아니고 전달되어도 무시합니다. 종료 중복 실행 방지(#47)와 알림 중복 생성 방지(`dedupe_key`)는 필수입니다.
- 입찰은 Auction 락 후 서버 시각으로 판정하며 Bid에 같은 시각을 기록합니다. 타임 경매의 연장도 같은 락 안에서 같은 판정 시각으로 결정합니다.
- 화면의 남은 시간은 서버 시각(`serverTime`)에 맞춰 표시합니다. 판정 근거는 언제나 서버입니다.
- WebSocket 이벤트는 커밋 뒤에 보내며 화면의 유일한 근거가 아닙니다. 다시 연결하면 REST로 상태를 맞춥니다.
- 사전 예고가 참여를 늘린다는 효과는 검증되지 않았습니다. 이를 성과로 주장하지 않습니다.

## 선행 작업과 미결

작업 순서는 기반 작업(#83~#90)을 먼저 하고 그 위에 타임 경매 작업을 올립니다. 정확한 발표일은 미정입니다. 개인별 책임은 각 이슈의 Assignees와 [협업 규칙](../00-team-and-collaboration.md)을 따릅니다. 기존 지역 필드·스키마를 전국 전환이라는 이유로 제거하지 않습니다.
