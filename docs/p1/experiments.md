# P1 실험과 측정 기준

이 문서는 앞으로 수행할 검증의 기준입니다. 아직 성능 수치나 검증 결과는 없습니다. 기능 완료와 효과 검증을 구분합니다. 이상입찰 탐지 실험은 보류해 [보류 계획](../later/anomaly-bid-detection.md)으로 옮겼습니다.

| 검증 | 방법 | 보고할 결과 |
|---|---|---|
| 입찰·종료 경계 | 실제 MySQL에서 마감 시각 경계의 입찰과 종료 처리를 동시에 실행 (C02, #47의 C08) | 락 뒤 판정 시각이 `endAt` 미만인 입찰만 성공, 종료 후 새 Bid 없음 |
| 타임 경매 연장·종료 경합 | 마지막 1분 안 입찰과 종료 처리를 동시에 실행, 여러 입찰이 연달아 연장하는 경우 포함 | 연장된 `endAt`·연장 횟수·원래 종료 시각이 서로 맞고, 종료 처리는 연장된 시각 이후에만 확정 |
| 시작 알림 | 같은 경매의 시작 알림 처리를 중복·동시 실행 | 관심상품 등록자마다 알림이 하나만 생김 |
| 입찰 성능 | 한 경매에 입찰이 몰리는 부하(예: k6)를 같은 조건으로 반복 | 입찰 응답 p50/p95/p99·오류율·락 대기, 측정 환경·단위·구간 |

## 마감 편성 시뮬레이션 검토

수요 기반 마감 편성을 빼기 전에, 종료 시각 추천을 합성 경매 시뮬레이터로 먼저 검토했습니다. 아래 수치는 서비스 기록이 아니라 모형 안의 값입니다.

- 추천 효과가 가정한 구매자 활동 시간에 따라 뒤집혔습니다(활동량 TOP3: 저녁 피크 +5.5%, 낮 피크 −11.0%).
- 시뮬레이터의 답을 정하는 활동 시간·경쟁 강도가 가정이라, 이 결과로 실제 시장의 효과를 말하지 않습니다.
- 실제 효과는 서비스 기록이 쌓인 뒤 일부 판매자에게만 추천을 보여 주는 비교로 확인할 수 있습니다. P1에서는 하지 않습니다.
- 시뮬레이터 코드와 기록은 P1에서 쓰는 곳이 없어 저장소에 올리지 않고 담당자 로컬에 보관합니다.

## 재현

- 테스트와 측정에 쓴 시드·코드 버전·설정·실행 명령·결과와 실패 사례를 보관합니다.
- 시간에 따라 달라지는 테스트는 주입한 `Clock`으로 시각을 고정합니다.
- 환경·단위·측정 구간을 명시하며 테스트 통과 횟수를 처리량으로 표현하지 않습니다.

HTTP 요청 멱등 기능과 C09는 후순위입니다. 종료의 중복 실행 방지(#47)와 알림 중복 생성 방지는 P1에서 검증합니다.
