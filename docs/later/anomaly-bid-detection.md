# 이상입찰 탐지 — 보류

2026-10-31 이상입찰 탐지를 P1 최종 시연 범위에서 빼고 보류했습니다. 시작 시기는 정하지 않았지만 언젠가 다시 진행할 기능이라, P1 문서에 있던 계획을 이 문서로 옮겨 둡니다. 구현된 것은 없으며 아래 내용은 모두 계획입니다. 결정은 [결정 로그](../04-decisions.md)에 있습니다.

## 목표

논문(LSS)을 근거로 입찰 행동을 분석하고, 경매 진행 중 위험 점수·판단 근거·오탐 감소 결과를 관리자에게 보여 줍니다. 판매자와 관련된 계정의 가격 부풀리기 같은 의심 행동을 검토하는 것이 목적입니다.

필요했던 결과: 온라인 특성·위험 점수·오탐 감소·데이터 부족·근거·버전, 입찰 커밋 후 분석, 관리자 권한과 화면, 공개 데이터 비교와 합성 시나리오 평가.

선택으로 두었던 확장: MRF/LOF.

## 설계에서 지킬 경계

- 위험 점수는 확률이나 부정 확정 판정이 아닙니다. 자동 차단하지 않고 오탐 감소·최소 표본·데이터 부족을 포함합니다.
- 논문에서 확인한 지표·가중치·PFP와 자체 규칙을 구분합니다. 원문은 2026-10-30 확보했고 확인한 내용은 #61에 정리돼 있습니다.
- 분석은 입찰 성공 커밋 후 별도로 처리합니다. 위험 분석 계산·외부 호출을 입찰 트랜잭션 안에 넣지 않고, 기존 Auction → 입찰자 User(FOR SHARE) 락 순서를 바꾸지 않습니다([락 규칙](../backend/locking.md)).
- 분석 이벤트는 입찰 식별자 기준으로 중복 처리를 막고 실패 시 재처리합니다. HTTP 요청 멱등성(C09)과는 다른 문제이므로 혼동하지 않습니다. 화면 이벤트(WebSocket)의 유실 허용을 분석 이벤트에 그대로 적용하지 않습니다([실시간 설계](../api/realtime.md)).
- 관리자 권한은 분석 조회에 필요한 만큼만 만들고 일반적인 관리자 기능 전체를 개발하지 않습니다.

## 화면

관리자 위험 분석 화면: 입찰 타임라인·점수 변화·근거·시각·버전·데이터 부족·분석 대기/실패.

## 실험 기준

| 실험 | 입력과 비교 | 보고할 결과 |
|---|---|---|
| 오프라인 분류 | 원출처·레이블 의미를 확인한 공개 데이터, 기준 모델/Random Forest (XGBoost 선택) | Precision·Recall·F1·PR-AUC·FPR·추론 지연. 실제 부정 확정/온라인 LSS 성능으로 일반화하지 않음 |
| 온라인 탐지 | 현재 시점까지의 실제 입찰 경로와 사전 정의한 합성 정상/의심 이력 | 규칙/원문 적용 모델·오탐 감소 전후, 데이터 부족·탐지 지연·근거 |

- 같은 입찰자·경매·시간 이력의 교차 의존성을 확인하고 평가 질문에 맞는 분할을 선택합니다. 원출처·버전·레이블 생성 방법을 기록하고 전처리·튜닝은 훈련 데이터 안에서 수행합니다.
- 진행 중에는 미래 낙찰 결과나 종료 후 특성을 사용하지 않습니다. 공개 데이터의 계산된 특성만으로 원시 이벤트 기반 모델을 동일 조건 평가했다고 주장하지 않습니다.
- 합성 시나리오에는 정상 입찰자가 의심처럼 보이는 경우도 넣고, 실제 입찰 API와 가격 단위·선두 수동입찰 금지 정책을 지킵니다.
- 성능은 분석 도입 전후를 같은 조건으로 비교하고, 입찰 응답 p50/p95/p99와 별도로 커밋 후 분석 반영 지연을 기록합니다.

## 시연 시나리오

1. 사전 정의한 의심 입찰과 필요한 과거 이력을 합성 시나리오로 실행합니다. 실제 입찰 정책을 지킵니다.
2. 관리자가 커밋 후 분석의 대기/완료·위험 점수 변화·근거·버전·데이터 부족을 확인합니다.
3. 관리자 접근 거절·분석 실패도 확인합니다.
4. 공개 데이터와 합성 시나리오의 비교 결과·오탐·한계, 분석 지연을 구분해 설명합니다. 외부 논문 수치를 자체 성과로 제시하지 않습니다.
